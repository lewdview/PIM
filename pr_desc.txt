💡 What: Extracted the progress slider logic (which depends on the highly volatile `currentTime` state from the audio's `timeupdate` event) into a new isolated child component (`PlaybackProgress`). Introduced a `playbackId` mechanism to ensure the child successfully re-attaches listeners upon imperative track restarts.
🎯 Why: Previously, `ListenPage.tsx` directly subscribed to `timeupdate`, meaning the entire large component (including a canvas visualizer and a dynamic playlist map) was forced to rapidly re-render multiple times a second during audio playback. This caused excessive React render tree overhead and degraded the framerate.
📊 Impact: Reduces unnecessary re-renders of the large parent `ListenPage` component by 100% during playback, confining the 60fps state updates strictly to the small slider element.
🔬 Measurement: Verify by using React Developer Tools Profiler and recording a playback session; `ListenPage` should no longer show continuous thick flame graph bars during playback.
