
## 2025-02-27 - Hardcoded Admin Passphrase Removal
**Vulnerability:** A critical vulnerability where a hardcoded admin passphrase was embedded in the client-side frontend bundle within `src/pages/AdminPage.tsx` and `src/pages/BeatmapEditor.tsx`.
**Learning:** Storing secrets or administrative passwords directly in the source code exposes them to anyone who examines the client bundle. This happens frequently when creating simple gating mechanisms on the frontend without a dedicated backend auth route.
**Prevention:** For client-side-only authentication gates, developers should rely on cryptographic hashes. Use `window.crypto.subtle.digest` to evaluate entered passphrases against a stored hash value (e.g., SHA-256) instead of keeping the raw secret exposed in the JS bundle. If background services strictly require the raw passphrase payload, store it temporarily in `sessionStorage` post-authorization.

## 2025-02-27 - Hardcoded API Keys in Fallbacks
**Vulnerability:** A hardcoded dummy API key was used as a fallback for the `VITE_FIREBASE_API_KEY` environment variable in `src/lib/firebase.ts`. Although this specific key was a dummy, using dummy keys as fallbacks in configuration files is an anti-pattern. If the environment variable isn't injected during the build, the dummy key gets bundled, causing the application to proceed with invalid credentials instead of failing fast. This could potentially leak secrets if a developer decides to put a real key as a fallback for local testing and accidentally commits it.
**Learning:** Fallback values for critical secrets (like API keys) in frontend configuration files (e.g., `import.meta.env.VITE_API_KEY || "..."`) should always be empty strings or `undefined`. This ensures that runtime assertions fail immediately when the environment variable is missing, preventing bypass vulnerabilities or exposing real keys added for convenience.
**Prevention:** When setting up environment variable loading for frontend applications, always default to `""` or omit the fallback entirely for sensitive values. Never use functional dummy strings or development keys in production configurations.
