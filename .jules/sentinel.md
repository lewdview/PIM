## 2024-05-18 - Client-Side Hardcoded Secrets vs. Backend Passthrough Requirements
**Vulnerability:** A hardcoded admin passphrase was stored in plaintext directly in the React frontend bundle for `AdminPage.tsx` and `BeatmapEditor.tsx`.
**Learning:** Removing the hardcoded plaintext string and replacing it strictly with a client-side SHA-256 hash validation solves the exposure. However, the plaintext input needs to be cached via `sessionStorage.setItem('th3vault_admin_pass', input)` upon successful login because the backend edge functions (like `updateAdminConfig`) rely on receiving this plaintext passphrase as an argument. Dropping the plaintext state completely would break the `prompt()` fallback loops and API invocations elsewhere in the application.
**Prevention:** When mitigating hardcoded client secrets, always check if the token/passphrase is being passed downstream to backend services before completely omitting it from application state. Use `crypto.subtle.digest` for client-side hashing checks to hide it from the static bundle while storing the inputted value in ephemeral or session storage if required by backend routes.
