## 2025-02-18 - [Optimize Zustand subscriptions in list components]
**Learning:** Destructuring entire Zustand stores (`const { a, b, c } = useStore()`) in components rendered many times (like in a list) can cause massive O(N) re-renders, especially if the store has high-frequency updates like audio time `progress` or `currentTime`. This is a significant bottleneck in React list virtualization and rendering performance.
**Action:** When subscribing to Zustand stores in list components, avoid destructuring. Instead, use granular selectors for each property. For values that update frequently but are only relevant to the "active" item, use conditional selectors (e.g., `useStore(s => isActive ? s.progress : 0)`) so inactive items return constant values and safely avoid re-rendering, all without violating the Rules of Hooks.
