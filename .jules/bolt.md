## 2024-05-24 - Zustand Granular Selectors with Fast-Updating State
**Learning:** Destructuring a Zustand store (`const { a, b } = useStore()`) causes the component to re-render whenever *any* state in the store changes. Using granular selectors (`const a = useStore(s => s.a)`) is better, but still causes re-renders if the component relies on rapidly changing state like playback `progress` or `currentTime`. This is a severe performance bottleneck in large UI components (like `GlobalPlayerBar`) that contain album art, links, and complex layouts.
**Action:** Always use granular selectors for Zustand. Furthermore, when a component subscribes to fast-updating state (like a media progress bar), extract *only the UI that depends on that state* into isolated child components. This prevents the entire parent component from re-rendering at 60fps during playback.
